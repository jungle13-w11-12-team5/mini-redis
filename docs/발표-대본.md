# 발표 대본 — 미니 레디스 개발 (4분)

> 시연 전: `bash scripts/reset.sh` 실행 → 브라우저에서 http://127.0.0.1:8088 열어 두기.
> [화면]은 시연 동작, 나머지는 말할 내용.

## 1. 시작 (0:00 – 0:20)

저희는 미니 레디스를 만들었습니다.

저희에게는 지난주에 만든 미니 DBMS가 있었습니다. 그래서 레디스를 DB 앞에 붙이면 실제로 얼마나 빨라지는지 직접 비교해 보고 싶었습니다. 과제에 없던 일이지만 둘을 합쳐서 비교했습니다.

## 2. DBMS에 수정 기능 넣기 (0:20 – 0:45)

먼저 문제가 있었습니다. 저희 DBMS에는 수정 기능이 없어서, DB 값이 바뀌었을 때 캐시가 맞춰지는지 시험할 수 없었습니다.

DBMS는 데이터가 깨지지 않게 하려고 파일에 쓴 내용을 고치지 않고 뒤에 이어서만 씁니다. 그래서 수정은 바뀐 행을 파일 끝에 새로 쓰고, 마지막 것을 최신으로 보도록 바꿨습니다. 대신 수정할수록 파일이 커집니다.

## 3. 미니 레디스 (0:45 – 1:45)

레디스는 Java로, 외부 라이브러리 없이 만들었습니다. 진짜 레디스와 같은 통신 규칙을 따라서, 실제 레디스 도구를 그대로 붙여 쓸 수 있습니다.

해시 테이블은 키가 칸 수만큼 차면 두 배로 늘립니다. 한 번에 다 옮기면 그동안 서버가 멈추기 때문에, 요청마다 한 칸씩 나눠서 옮깁니다.

동시에 여러 명이 접속해도 명령은 스레드 하나가 하나씩 실행합니다. 그래서 락이 필요 없고, 명령이 중간에 끊기지 않습니다.

만료된 키는 읽을 때 확인해서 지우고, 아무도 안 읽는 키는 0.1초마다 20개씩 뽑아 지웁니다.

## 4. 단순 비교 (1:45 – 2:10)

그런데 DB 앞에 붙여 보니 id 조회는 차이가 거의 없었습니다. DB가 인덱스로 찾아서 이미 빨랐기 때문입니다. DB에 다녀오면 2ms, 레디스에 다녀오면 0.8ms였습니다.

그래서 웹 서버와 화면을 만들어 실제 요청이 지나가는 길 전체를 붙여 봤습니다.

## 5. 시연 (2:10 – 3:20)

[화면] `이름으로 검색`을 두 번 누른다.

이름 검색은 DB가 10만 행을 전부 확인해야 해서 오래 걸립니다. 처음에는 DB까지 가서 20ms, 두 번째는 레디스에서 가져와서 2ms입니다. 아래 막대에서 파란 DB 시간이 사라집니다.

[화면] `id로 조회` 한 번 → 나이를 바꾸고 `DB만 수정` → `id로 조회` 다시.

DB만 수정하면 레디스는 모르기 때문에 옛 값이 그대로 나옵니다. 그래서 수정할 때 캐시도 지워야 합니다.

[화면] 상단 무효화를 `키 삭제`로 바꾸고 `경합 재현`.

그런데 키를 지우는 것만으로는 부족합니다. 한 요청이 DB에서 옛 값을 읽어 가는 사이에 다른 요청이 수정하고 키를 지우면, 먼저 요청이 옛 값을 다시 넣어 버립니다. 빨간색처럼 옛 값이 남습니다.

[화면] `버전 번호`로 바꾸고 `경합 재현`.

그래서 캐시 키 이름에 버전 숫자를 넣고, 수정할 때마다 버전을 올렸습니다. 늦게 들어온 옛 값은 아무도 읽지 않는 옛 이름에 들어가서 문제가 없습니다.

## 6. 결과 (3:20 – 3:50)

부하 도구로 같은 조건을 3번씩 쟀습니다.

이름 검색은 28.8ms에서 10.7ms로 약 3배 빨라졌습니다. id 조회는 7.5ms에서 7.4ms로 차이가 없었습니다. 그리고 수정이 100번에 1번만 섞여도 캐시를 켠 쪽이 더 느렸습니다. 수정할 때마다 버전이 올라 캐시가 전부 버려지기 때문입니다.

## 7. 마무리 (3:50 – 4:00)

캐시는 조회가 오래 걸리고 데이터가 잘 바뀌지 않을 때만 효과가 있었습니다. 감사합니다.

## 예상 질문 (시간 밖)

| 질문 | 답 |
|---|---|
| 서버가 꺼지면 데이터는? | 구현하지 않았습니다. 여기서 레디스는 DB의 복사본이라 다시 채울 수 있습니다. 명령을 1초마다 파일에 기록하는 방식만 설계했습니다 |
| 왜 스레드 하나인가? | 해시 조회 하나가 매우 짧아서 여러 스레드로 나눠도 얻는 게 적고, 락이 없으면 동시성 문제가 구조적으로 생기지 않습니다. 대신 오래 걸리는 일은 나눠서 합니다 |
| 측정값을 믿을 수 있나? | 노트북 CPU 2개에서 모두 돌아 처리량이 회차마다 최대 2.5배 흔들립니다. 그래서 3번 재서 같은 방향으로 나온 것만 결론으로 썼고, 측정마다 데이터를 처음 상태로 되돌렸습니다 |
| 버전 번호 방식의 단점은? | 행 하나만 바뀌어도 테이블 캐시 전체를 새로 채웁니다. 결과 3번이 그 대가입니다. 수정이 잦으면 키 단위로 지우고 다른 방법으로 순서 꼬임을 막아야 합니다 |
| 해시 테이블 크기를 늘리는 중에 조회하면? | 옛 배열과 새 배열을 둘 다 찾습니다. 새 키는 새 배열에만 넣어서, 키 하나는 항상 한쪽에만 있습니다 |
